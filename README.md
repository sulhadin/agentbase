# agentbase

Single source of truth for the AI agent config every repo in the org shares — rules, skills, Claude Code subagents and commands. Consumers pull it with [rulesync](https://github.com/dyoshikawa/rulesync); a tagged release here opens a PR in every consumer automatically.

```
rules/<name>.md            shared rules  → fetched by consumers via rulesync `sources`
skills/<name>/SKILL.md     shared skills → fetched by consumers via rulesync `sources`
.rulesync/subagents/       Claude-only   → packaged into plugins/agentbase (marketplace)
.rulesync/commands/        Claude-only   → packaged into plugins/agentbase (marketplace)
plugins/agentbase/         generated by `npm run plugin`; committed; CI fails if stale
templates/                 files adopt.sh drops into a consumer repo
scripts/adopt.sh           one-time consumer onboarding
```

## How it flows

1. Change a rule/skill/subagent here, open a PR, merge.
2. Add a `CHANGELOG.md` entry, tag `vX.Y.Z`, push the tag.
3. `release.yml` publishes the GitHub release and calls `sync.yml`, which finds every repo with the `agentbase-consumer` topic, bumps its `rulesync.jsonc` ref, runs `rulesync install --update && rulesync generate`, and opens/updates a `chore/agentbase-sync` PR there.
4. Consumers review and merge. Their CI (`agentbase-check.yml`) regenerates from the lockfile and fails on drift, so generated files can't be hand-edited.

Subagents/commands don't go through `sources`; they ship as a Claude Code plugin from this repo's marketplace and update on `claude plugin update` without a PR.

## Onboarding a consumer repo

From the consumer repo root:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/sulhadin/agentbase/main/scripts/adopt.sh) sulhadin
```

It imports existing tool config into `.rulesync/`, writes `rulesync.jsonc` pinned to the latest release, adds the `.curated/` gitignore entries, `.claude/settings.json` (marketplace), the drift-check workflow, removes the old symlinks, runs install + generate and adds the repo topic. Then: delete from `.rulesync/` whatever agentbase already ships, append `templates/codeowners-snippet` to `CODEOWNERS`, commit everything including generated files.

Local-vs-shared rule: a repo-specific `.rulesync/rules/<name>.md` or `.rulesync/skills/<name>/` with the same name as a shared one overrides it.

## Conventions for content here

- `rules/*.md` are flat (no subfolders — rulesync ignores nested rules) and never `root: true`; each consumer keeps its own root rule.
- Frontmatter must not set `targets` on subagents/commands, or the plugin target is filtered out.
- Generated files are committed everywhere on purpose: cloud/background agents and fresh clones must see them without running anything. Do **not** run `rulesync gitignore` in consumers.

## One-time setup

- GitHub App with `contents: write`, `pull_requests: write`, `metadata: read` installed on the org; store `AGENTBASE_APP_ID` / `AGENTBASE_APP_PRIVATE_KEY` as repo secrets here.
- If this repo is private, consumers' CI needs a read token for `rulesync install` (`AGENTBASE_READ_TOKEN`), and developers need `GITHUB_TOKEN`/`GH_TOKEN` in their shell (`export GITHUB_TOKEN=$(gh auth token)`).
- Team `@sulhadin/platform` exists for CODEOWNERS.
